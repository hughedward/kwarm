# Swarm Visualizer Backend

## Overview

The Swarm Visualizer backend captures events from a running Swarm system, typically using the `devtalib/swarm` library, and broadcasts these events in real-time over WebSockets. This allows a frontend application to visualize the Swarm's operations, including agent creation, interactions, tool calls, and handoffs.

The system is designed to be minimally intrusive by monkey-patching key methods in the Swarm library. If the actual Swarm library is not found in the environment, mock objects are used to simulate Swarm behavior for demonstration and testing of the visualization pipeline.

## Key Components

*   **`monkey_patcher.py`**:
    *   **Approach:** This module dynamically alters the behavior of the Swarm library at runtime. Instead of modifying the Swarm library's source code directly, `monkey_patcher.py` replaces specific Swarm methods with wrappers. These wrappers execute the original method's logic and then emit events based on the method call and its outcome.
    *   **Patched Methods (Examples):**
        *   `Swarm.__init__`: To capture agent definitions.
        *   `Swarm.run` (or equivalent main execution method): To capture the start and end of a Swarm run, and initial agent activation.
        *   `Agent.get_chat_completion` (or Swarm's equivalent): To capture LLM requests and responses.
        *   `Swarm.handle_tool_calls`: To capture attempts to call tools.
        *   `Swarm.handle_function_result`: To capture the results of tool calls.
    *   **Async Handling:** The patcher is designed to work with an asynchronous backend (FastAPI). If patched methods are synchronous, event emissions are scheduled on the running asyncio event loop (using `asyncio.create_task`) to prevent blocking.
    *   **Mock Objects:** If the `swarm` library is not installed, dummy `Swarm` and `Agent` classes within `monkey_patcher.py` (and `main.py`) are used. These mocks simulate the structure and behavior of the actual Swarm components, allowing the backend and frontend to function for demonstration purposes.

*   **`event_definitions.py`**:
    *   **Purpose:** Defines the schema for all events that can be emitted by the system. These are Pydantic models ensuring data consistency.
    *   **Key Event Types:**
        *   `SwarmRunStartEvent`, `SwarmRunEndEvent`: Mark the beginning and end of a Swarm execution.
        *   `AgentDefinitionEvent`: Describes an agent's properties (name, tools, instructions hash).
        *   `AgentActivateEvent`, `AgentDeactivateEvent`: Indicate when an agent becomes active or inactive.
        *   `AgentHandoffEvent`: Signals that control or a task is passed from one agent to another.
        *   `ToolCallAttemptEvent`, `ToolCallResultEvent`: Log tool call attempts and their outcomes.
        *   `LLMRequestEvent`, `LLMResponseEvent`: Track interactions with language models.
        *   `ErrorEvent`: For reporting errors occurring within the Swarm or visualization patches.
    *   Refer to the Pydantic models in the file for the detailed structure of each event.

*   **`event_emitter.py`**:
    *   **Purpose:** Manages WebSocket clients and broadcasts events to them.
    *   **Functionality:**
        *   Maintains a list of connected WebSocket clients.
        *   The `emit(event_name, data)` method serializes the Pydantic event model (`data`) to JSON and then calls `broadcast()`.
        *   `broadcast(message)` sends the JSON message to all currently connected clients asynchronously.

*   **`main.py`**:
    *   **WebSocket Server:** This script runs a FastAPI application, which serves as the WebSocket server.
    *   **Endpoint:** It exposes a WebSocket endpoint at `/ws/swarm_events`.
    *   **Connection Management:** When a client connects, it's added to the `EventEmitter`. On disconnection, it's removed.
    *   **Patching Activation:** Calls `apply_patches()` from `monkey_patcher.py` on server startup to activate the Swarm event capturing.
    *   **Example Run:** Includes an example of initializing and running a (mock) Swarm. Events generated by this example are broadcast to connected clients, demonstrating the system's functionality.

*   **`__init__.py`**:
    *   This empty file ensures that the `swarm_visualizer` directory is treated as a Python package, allowing for correct module imports (e.g., `from swarm_visualizer.main import app`).

## Setup and Running

1.  **Python Version:** Python 3.8+ is recommended.
2.  **Virtual Environment (Recommended):**
    It's highly recommended to use a virtual environment to manage project dependencies.
    ```bash
    python -m venv venv
    source venv/bin/activate  # On Windows use `venv\Scripts\activate`
    ```
    Ensure your virtual environment is activated before installing dependencies and running the server.

3.  **Dependencies:**
    *   `fastapi`: For the web framework and WebSocket server.
    *   `uvicorn[standard]`: ASGI server to run FastAPI (includes `websockets` and `httptools`).
    *   `pydantic`: For event data modeling.
    *   (Optional) `devtalib/swarm`: The actual Swarm library. If not present, mock objects will be used.

    A `requirements.txt` file is provided. Install dependencies using:
    ```bash
    pip install -r requirements.txt
    ```
    (If you are in the `swarm_visualizer` directory, you might need `pip install -r requirements.txt`. If you are in the project root, use `pip install -r swarm_visualizer/requirements.txt`.)


4.  **Running the Server:**
    *   **Directory:** To run the Uvicorn server correctly, ensure you are in the **parent directory** of the `swarm_visualizer` package. For example, if your project structure is `my_project_root/swarm_visualizer/main.py`, you should be in `my_project_root`.
    *   **Command:**
        ```bash
        python -m uvicorn swarm_visualizer.main:app --reload --port 8000
        ```
    *   `--reload`: Enables auto-reload on code changes (for development).
    *   `--port 8000`: Specifies the server port. The frontend will connect to this port.

## How it Works

1.  **Initialization:** When the FastAPI server starts (`main.py`), it calls `apply_patches()`.
2.  **Patching:** `monkey_patcher.py` replaces methods on the (real or mock) Swarm classes with custom wrappers.
3.  **Swarm Operation:** As the Swarm library (or its mock equivalent, e.g., during the example run in `main.py`) executes, calls to the patched methods trigger the wrappers.
4.  **Event Emission:**
    *   The wrapper functions gather relevant data and create Pydantic event models (from `event_definitions.py`).
    *   They then call `emitter.emit(event_name, event_data)`.
5.  **Broadcasting:**
    *   `event_emitter.py`'s `emit` method serializes the event to JSON.
    *   The JSON string is then passed to `broadcast()`, which sends it to all connected WebSocket clients (e.g., the frontend application).
6.  **Real-time Visualization:** The frontend receives these events and updates its display accordingly.
